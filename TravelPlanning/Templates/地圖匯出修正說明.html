Google Map 匯出 Word 圖片修正

TravelPlanning — 匯出行程 Word 時地圖截圖沒有 marker、中心點錯誤的問題

問題現象

從 UI 手動切換日期時,地圖畫面正常;但透過 ExportDataToWord() 匯出時,產生的地圖圖片不對。把兩份 docx 的圖抽出來比對:

test.docx(UI 手動)output1.docx(程式匯出)
地標 marker有,都落在當日地點上完全沒有
路線 polyline有有,但部分天數缺少
地圖中心 / 縮放對準當日路線多天視野一模一樣,停在前一次的位置

原因

症狀是「路線畫到了、marker 沒到、視野停在上一步」,屬於典型的截圖比畫面早一步的競態(race condition)。

  1. marker 是非同步後補上去的。 AddMarkerandToolTip 原本是 async void,而且在 mapControl.AddMarker 之前會先 await googleAPIContext.Place.PlacePhoto(...)。LoadCurrentDayMapAsync() 只是用 Messenger 把 place 丟出去就 return 了,marker 其實是之後才被加到地圖上 → 匯出迴圈立刻 ToImage(),自然抓不到 marker。 更糟的是下一天設定 CurrentDay 時 ClearMap() 又把遲到的 marker 清掉,結果每一天都是空的。
  2. 圖磚與畫面還沒更新。 GMap 的圖磚(tile)是背景執行緒下載,地圖 zoom-to-fit 也需要一次 WPF render pass。 await 一回來就 ToImage(),內部的 RenderTargetBitmap 抓到的是上一幀, 所以中心點停在前一天的位置。

修正內容

1. marker 建立流程改成可等待

Views\Pages\Trip\TripDetailPage.xaml.cs
// 正在進行中的 marker 建立流程(含 PlacePhoto 的網路請求)
private readonly List<Task> pendingMarkerTasks = new List<Task>();

- public async void AddMarkerandToolTip(object sender, PlaceDetailResModel e)
+ public void AddMarkerandToolTip(object sender, PlaceDetailResModel e)
+ {
+     // 記下這個 task,匯出截圖時才知道 marker 有沒有真的加完
+     pendingMarkerTasks.Add(AddMarkerandToolTipAsync(e));
+ }
+
+ private async Task AddMarkerandToolTipAsync(PlaceDetailResModel e)
  {
      ... 原本的內容 ...
  }

Messenger 的 handler 必須是 void,所以保留一個同步的 handler 當入口,實作搬到 AddMarkerandToolTipAsync,並把 Task 收進 pendingMarkerTasks,外部才有辦法知道 marker 加完了沒。

2. 新增 CaptureMapImageAsync:截圖前先等畫面就緒

Views\Pages\Trip\TripDetailPage.xaml.cs
/// 截圖前先確定「當日的 marker 都已經加到地圖上、而且畫面真的畫完了」,
/// 否則 ToImage 抓到的會是上一幀(沒有 marker、中心點停在前一天)。
private async Task<byte[]> CaptureMapImageAsync(int pixelWidth)
{
    // 1. 等所有 marker 的非同步流程跑完(AddMarkerandToolTip 會先 await PlacePhoto)
    while (pendingMarkerTasks.Count > 0)
    {
        Task[] tasks = pendingMarkerTasks.ToArray();
        pendingMarkerTasks.Clear();
        await Task.WhenAll(tasks);
    }

    Control mapVisual = (Control)mapControl;
    mapVisual.UpdateLayout();

    // 2. 等圖磚下載完、地圖 zoom-to-fit 到當日路線
    await Task.Delay(MapSettleDelayMs);   // MapSettleDelayMs = 1500

    // 3. 讓 WPF 完成一次 render pass,RenderTargetBitmap 才抓得到最新畫面
    await Dispatcher.InvokeAsync(() => { }, DispatcherPriority.Background);

    return mapControl.ToImage(pixelWidth);
}

同時把 delegate 的接線換掉,並在 ClearMap() 內一併清除 pendingMarkerTasks:

- newContext.CaptureMapImage = (pixel) => mapControl.ToImage(pixel);
+ newContext.CaptureMapImage = CaptureMapImageAsync;

(前一步)圖片縮放到 390px

ViewModels\TripDetailContext.cs
private byte[] ResizeImageByteArray(byte[] imageData, int pixelWidth)
{
    if (imageData == null || imageData.Length == 0) return imageData;

    BitmapImage bitmapImage = new BitmapImage();
    using (MemoryStream input = new MemoryStream(imageData))
    {
        bitmapImage.BeginInit();
        bitmapImage.CacheOption = BitmapCacheOption.OnLoad;   // 讀完就關掉 stream
        bitmapImage.StreamSource = input;
        bitmapImage.DecodePixelWidth = pixelWidth;            // 高度自動等比例
        bitmapImage.EndInit();
        bitmapImage.Freeze();
    }

    using (MemoryStream output = new MemoryStream())
    {
        BitmapEncoder encoder = new PngBitmapEncoder();
        encoder.Frames.Add(BitmapFrame.Create(bitmapImage));
        encoder.Save(output);
        return output.ToArray();
    }
}
CacheOption = OnLoad 一定要設在 StreamSource 之前,否則 using 關掉 MemoryStream 後圖會讀不到。

後續注意事項

  • 延遲時間是估計值。MapSettleDelayMs = 1500 偏保守。網路慢時仍可能出現灰色圖磚,可以再調大; 要更精準的話,可以從 visual tree 撈出底層的 GMapControl,改監聽它的 OnTileLoadComplete 事件 (GMap.NET 有這個事件,但 IMapControl 介面沒有往外開放)。
  • 只有一個地點的那天不會重新定位。LoadCurrentDayMapAsync() 需要 TripDayPlaces.Count >= 2 才會送出路線,否則地圖不會 zoom-to-fit,視野會停在前一天。 要修的話得在無路線時自行把地圖中心移到該地點,但 IMapControl 目前沒有看到設定 center 的 API。
  • 匯出過程畫面會逐日跳動(因為是真的在操作地圖截圖),每天大約多 1.5 秒。 可以考慮在匯出期間蓋一層「匯出中…」遮罩。
